# Notice PDF and requirement checklist evidence, 5 November 2026

Branch `feat/notice-pdf-checklist`, on top of `main` `0e4f598`. Migration `0032_grant_notice_checklist`. Scope: `GRANT_PLATFORM_PLAN.md` §6, item 1 (week 1 of the build the owner asked for on 5 November 2026). Every notice, organization and opportunity here is synthetic. No real notice is committed: the test PDFs are generated by `artifacts/api-server/src/lib/grants/syntheticNotice.ts` (pdfkit) and, in the browser spec, written by hand in `artifacts/content-os/e2e/notice.spec.ts`.

## What was verified

| Behavior | How |
|---|---|
| Upload goes through the same storage as source PDFs (`lib/sourceStorage.ts`) and is checked for size and the `%PDF-` header | Unit and integration tests; a text file named `.pdf` gets 400 "The file is not a PDF." |
| Link fetch: https only, public addresses only (the webhook SSRF protection), at most 3 redirects, a byte cap while streaming | Unit tests for the URL rules; integration test with a fake fetcher (the official link, and a link that returns a web page). The real network fetch was **not** exercised: this environment's proxy blocks outbound hosts such as grants.gov (403 on CONNECT) |
| Text read one page at a time with pdf.js, page cap applied and reported | Unit tests on a synthetic PDF (3 pages; 7 pages with a cap of 2) |
| Docling over HTTP when `DOCLING_SERVE_URL` is set, falling back to pdf.js with a recorded reason | Unit tests with a fake HTTP response shaped from the docling-serve documentation. **No real Docling service was run** |
| Every proposed row cites a page whose text holds its quotation; invented, wrong-page, uncited and out-of-range rows are dropped | Unit tests with a mocked AI response; integration test with a mocked model (2 kept, 2 dropped) |
| Rows are proposed, never confirmed on a person's behalf; confirm, edit, reject and restore record who did it | Integration test and browser spec |
| Without an AI key, rows come from labelled pattern matching (`demo_rules`), never from the demo model | Integration test and browser spec (the notice and each row say "pattern matching (demo, no AI)") |
| Workspace isolation | Integration test: another workspace gets 404 on all 8 notice and requirement routes |
| Roles | Integration test through the full router: writers reach every notice route; reviewers and viewers get 403 `forbidden_by_role` on writes and can read the page text. The per-route permission coverage test passes (new routes fall under the existing `grants.write` rule) |
| Files deleted with the notice, the application and the organization | Integration test checks the stored file is gone |

## Memory (512 MB instance)

Measured on the built server (`node ./dist/index.mjs`, Linux, Node 22, `NODE_ENV=test`), not on Render, so treat these as estimates.

| Measure | Result |
|---|---|
| Fresh server, idle | 240 MB resident |
| First 200-page synthetic notice (0.16 MB, text only), demo checklist | Peak 348 MB (+108 MB), 1.4 s. Most of the increase is pdf.js loading, and it stays loaded |
| Second 200-page notice on the same process | Peak 356 MB (+8 MB) |
| pdf.js alone, 50 / 200 / 400 pages | +105 / +108 / +110 MB: flat across page counts, so reading page by page keeps memory bounded |

**Risk.** 356 MB is just under the plan's 70%-of-plan target (358 MB of 512 MB), and a concurrent grant sync adds about 15 MB (`GRANT_STUDIO.md`, Capacity). Real notices with embedded fonts and images were not measured, because no real notice may be committed. The job kind runs one at a time per worker. Options if production memory shows it: run the reader in a worker thread that exits after each notice, or use the Docling backend (an owner decision). Owner: product owner; review after the first production week with notices.

Locally: `docker run -p 5001:5001 -e DOCLING_SERVE_API_KEY=change-me quay.io/docling-project/docling-serve`, then `DOCLING_SERVE_URL=http://localhost:5001`. On Render it would be a separate (likely paid) private service; Docling's models need far more than 512 MB. Not added to `render.yaml`.
2. **Optional limits.** `NOTICE_PDF_MAX_MB` (default 25) and `NOTICE_PDF_MAX_PAGES` (default 200) can be set in Render; the defaults need no action.
